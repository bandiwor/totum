# Органайзер — архитектура и спецификация

Личное PWA для iPhone. Без бэкенда, данные на устройстве, офлайн.
Документ — согласованная спецификация; код следует ему.

## Стек

| Слой | Решение |
|---|---|
| Язык | TypeScript strict (+ `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`) |
| Сборка | Vite 6 → статика для GitHub Pages (`base: './'`) |
| UI | Preact 10 + @preact/signals |
| Данные | IndexedDB (`idb`), одна таблица `[collection, id]` — новые коллекции без миграций БД |
| Валидация | valibot (импорт, схемы коллекций) |
| PWA | свой service worker (`src/sw/sw.ts`), список файлов внедряет `build/sw-plugin.ts` |
| Графики | свои SVG-компоненты (этап 3+) |
| Тесты | vitest для чистой логики (`src/core/*.test.ts`) |

## Три ядра, на которых держится всё

1. **Цикл** (`core/cycle.ts`) — шаблон на N дней с якорной датой. Расписание (14 дн.),
   программа тренировок, рационы (3 дн.), график работы (2/2) — один движок и один редактор.
2. **План → факт** (`core/plan.ts`) — на любую дату поверх шаблона кладутся правки
   `add / cancel / modify`. Пример: «в этот четверг дополнительная тренировка» — это
   `add` на дату, цикл не меняется. Перенос пары, съел больше, лишняя смена — то же самое.
3. **Таймлайн дня** (`core/timeline.ts`) — модули отдают `BusyBlock` (время + место),
   движок вставляет дорогу между местами и считает свободные окна.

## Места и дорога

- `Place` — дом, корпус универа, зал, работа… (`isHome` у одного).
- `Route` — минуты между двумя местами (по умолчанию в обе стороны).
- Алгоритм: день начинается и заканчивается дома. Между блоками в разных местах —
  прямой переход; если окно длинное и дома можно провести ≥ `minHomeStay` — дорога
  домой и обратно, а окно считается «дома». Не хватает времени — отметка «опоздание».
- Блок без места (`placeId: null`, онлайн-пара) не требует дороги.
- Любой новый модуль (работа и т.д.) получает это бесплатно, просто указывая `placeId`.

## Модули (фичи)

Каждый раздел — папка `src/features/<id>` и `FeatureDef` в `src/app/features.ts`.
Через реестр (`core/registry.ts`) фича подключается к: вкладкам, маршрутам,
супер-кнопке, виджетам «Сегодня», источникам занятости и агенде. Фичи не импортируют
друг друга напрямую — только данные (`model.ts`) там, где связь по смыслу.

### Супер-кнопка (FAB)
Полноэкранное меню из нескольких крупных плиток, всё за 1–2 нажатия.
- **Что сейчас** — короткий список с учётом времени: ближайшие пары/смены/тренировка,
  «Выйти в 8:20 → корпус 2», свободные окна, невыполненные задачи.
- **Еда** — отметить по плану / добавить сверх плана / изменить граммовку.
- **Приём и вода** — добавки, лекарства, вода (без КБЖУ).
- **Тренировка** — начать сегодняшнюю или добавить разовую.
- **Задача**, **Трата**, **Вес**, **Заметка**.
- Порядок плиток по `relevance()` (например, ближе к тренировке она поднимается выше).

### «Сегодня»
Лента дат (любой день), карточка свободного времени, таймлайн: блоки занятости, дорога
(«17:05 → Кофейня»), свободные окна, отменённые пары (нажать — вернуть), линия «сейчас».
Кнопка «Добавить» собирает `dayActions` всех фич: задача, разовая пара, разовая смена,
(далее — разовая тренировка). Ниже — виджеты фич (`todayWidgets`).

### План (этап 2)
- **Предметы**: название, цвет, преподаватель, аудитория, корпус (→ `Place`).
- **Типы пар**: редактируемый список (лекция, практика, лабораторная, семинар).
- **Сетка звонков**: «1 пара 8:30–10:00…» — при вводе выбирается номер пары.
- **Расписание** = цикл на N дней + версии по семестрам (дата начала; старые сохраняются).
- Правки на дату: отменить / перенести / заменить одну пару или изменить весь шаблон.
- **Задачи и ДЗ** — одна сущность; ДЗ = задача с предметом (и, при желании, с конкретной
  парой: «к следующей паре» подставляет дату).
- **Работа**: место работы (`Place`), график-цикл + разовые смены, ставка (час/смена/месяц)
  → занятость, дорога и ожидаемый доход в «Деньгах».
- **Неделя**: сетка 7 дней с блоками, дорогой и свободными окнами.

### Здоровье → Тренировки (этап 3)
- Справочник упражнений с категориями (грудь, спина, ноги…; список редактируется).
- Программа = цикл тренировочных дней (время + место для таймлайна); разовые тренировки
  через `add` на дату.
- Шаблон упражнения: подходы, диапазон повторов, вес, шаг веса, правило прогрессии.
- Лог: вес × повторы × **RPE** по подходам, самочувствие 1–5, заметка.
- **Авто-прогрессия** (план подстраивается под факт, вниз — никогда):
  - *Двойная прогрессия*: все подходы дошли до верха диапазона при RPE ≤ цели →
    следующий раз вес + шаг, повторы к низу диапазона; иначе цель = лучший результат + 1 повтор.
  - *Линейная*: успешная тренировка → вес + шаг.
  - *Только повторы* (собственный вес), *время* (планка).
  - Нет роста e1RM 3 тренировки подряд → статус «плато» (план держится, не снижается).
- **Аналитика**:
  - e1RM по Эпли `w·(1+r/30)`; с RPE — поправка на повторы в запасе: `r + (10 − RPE)`.
  - Тренд: регрессия по `ln(e1RM)` → «% в неделю».
  - Категория: индекс = медиана нормированных e1RM упражнений (база = медиана первых
    3 тренировок = 100%), тренд как выше; рабочие подходы в неделю; тоннаж.

### Здоровье → Питание и Тело (этап 4)
- **База продуктов**: КБЖУ на 100 г, порции («1 яйцо = 55 г»); **блюда** из продуктов.
- **Рационы** = цикл (рацион 1/2/3 или по дням недели), приёмы пищи с граммовкой.
- **День**: план → факт (съел по плану одним касанием, изменил граммовку, добавил лишнее,
  пропустил).
- **Приём и вода**: добавки, лекарства и прочее без КБЖУ: дозировка, единица, расписание
  (тоже цикл), отметки. Вода — счётчик с быстрыми кнопками.
- **Тело**: рост, возраст, пол, журнал веса; тренд веса = EMA (α≈0.1) + кг/нед по регрессии.
- **Нормы** (пересчитываются сами, можно зафиксировать вручную):
  - BMR: Миффлин–Сан Жеор (или Кэтч–Макардл, если известен % жира).
  - Расход: сначала BMR × активность; после ≥14 дней данных — **адаптивный**:
    `расход = средние ккал − Δвес_тренда(кг/день) × 7700`.
  - Цель: темп в % массы в неделю → дефицит/профицит ккал.
  - Белок: 1.6 г/кг на поддержке/наборе; в дефиците растёт с его глубиной до ~2.2–2.4 г/кг
    (Morton 2018; Helms 2014). При ожирении — на «опорную» массу, а не фактическую.
  - Жиры: не ниже 0.6 г/кг; 25–30% ккал на поддержке, в дефиците доля снижается к ~20%.
  - Углеводы: остаток.
  - Вода: ~30–35 мл/кг (редактируется).

### Деньги (этап 5)
- Операции: доход/трата, категория, дата, заметка.
- **Регулярные** (подписка, аренда): правило повтора → будущие плановые операции.
- **Запланированные разовые** (купить курсы в декабре): операция в будущем со статусом «план».
- **Растянутые**: трата с `spreadMonths` (курсы на 3 мес.) — в аналитике по месяцам
  делится на части, в остатке списывается в дату покупки.
- Доход от работы: ожидаемый из смен × ставка, подтверждается фактическим.
- **Цели**: сумма к дате → нужно откладывать в месяц; прогноз по средним накоплениям
  за 3 месяца.

### Записи (этап 6)
- Коллекции (дневник, книга, духи…) со **своими полями** (оценка, сезон, ссылка…).
- Запись: заголовок, текст, дата, теги, флажок «вернуться». Поиск по всему.

## Сквозное

- **Экспорт/импорт** — JSON в буфер / из буфера; проверка схемой; миграции версий
  (`core/store/migrations.ts`; локальная база мигрирует при запуске — версия хранится
  в записи `$meta`); **автокопия перед каждым импортом** (5 последних, можно
  восстановить).
- **Вибрация** (`core/haptics.ts`): Android — Vibration API; iOS — скрытый
  `<input type="checkbox" switch>` (iOS 18+ даёт системный отклик). Нативный `Switch`
  в UI-ките даёт отклик сам.
- **Ощущение нативности**: нет выделения/callout/зума, safe-area, свои жесты (свайп шита).
- **Обновления**: SW ставит новую версию в фоне и ждёт; плашка «Обновить» → `SKIP_WAITING`
  → перезагрузка. Проверка при каждом возврате в приложение.
- **Эффекты** (`core/fx.ts` → `ui/FxLayer.tsx`): искры, кольцо, конфетти через Web Animations
  API; при `prefers-reduced-motion` не рисуются.
- **Движение**: токены `--ease-enter`/`--ease-exit`/`--ease-emph` и длительности в
  `ui/tokens.css`. Переходы страниц — `app/ScreenStack.tsx` (уходящий экран живёт до конца
  анимации), меню супер-кнопки — рост подменю из нажатой плитки.
- **Цвет**: `core/color.ts` (OKLCH → sRGB с подрезкой хромы под гамут, контраст). Палитра
  (`app/theme.ts`) строится из одного оттенка акцента: светлота/хрома фиксированы для каждой
  темы, поэтому любой выбранный оттенок чистый и контрастный. Тёмная тема — AMOLED (#000).
- **Шрифты**: системные SF Pro Text/Display, `ui-rounded` для крупных чисел.

## Модули

Вклад фичи (вкладка, плитка быстрого меню, виджет «Сегодня», занятость, повестка, действия
дня) может иметь `module` — сама фича задаёт его по умолчанию (`FeatureDef.module`). Реестр
отдаёт только вклады включённых модулей, поэтому выключенный раздел пропадает отовсюду
сразу; данные остаются.

## Наборы

Приложение стартует пустым. Встроенные наборы — `features/packs/builtin.ts`, формат и правила
сопоставления — docs/PACKS.md, инструкция для ИИ — `core/packs/aiGuide.ts`. `planPack()`
делает «сухой прогон» (что добавится/изменится/удалится по разделам, с проверкой схем),
`applyPack()` делает автокопию и одну атомарную замену.

## Как добавить раздел

1. `src/features/<id>/model.ts` — типы + `defineCollection(...)` со схемой valibot.
2. `src/features/<id>/index.ts` — `FeatureDef` (вкладка, маршруты, плитки, виджеты, занятость).
3. Добавить в `src/app/features.ts`. Экспорт/импорт, «Сегодня», свободное время
   и супер-кнопка подхватят его сами.
4. Изменил формат существующих данных → поднять `SCHEMA_VERSION` и добавить миграцию.

## Локализация

`src/core/i18n`: словарь `ru` — источник правды, типы выводятся из него.
- `t('plan.week.title')` — ключ проверяется при компиляции (автодополнение).
- `t('tasks.left', { count: 3 })` — переменные `{name}` обязательны и типизированы.
- Множественное число: `{ one, few, many, other }`, форма выбирается `Intl.PluralRules`.
- `PlainKey` — ключи без переменных; ими подписываются вкладки, плитки, коллекции в реестре.
- Даты, дни недели, месяцы — через `Intl` по текущей локали.
- Встроенный язык: папка как `en/` с типом `LocaleMessages` + запись в `BUILTIN` в `languages.ts`.
- Свой язык: вставляется в Настройках как JSON (любая часть ключей); недостающие ключи берутся
  из выбранного запасного языка, переведённого на 100%. Хранится в коллекции `languages`.
